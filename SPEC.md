# ТЗ: «Пробный день» — попробуй IT-профессию за 30 минут

> Хакатон «Вайбкодинг ФКН», тема 1 «Без инструкции».
> Время на разработку: ~5 часов. Приоритет — **работающий основной сценарий**, а не полнота.

## 1. Идея

Человек хочет войти в IT, но не понимает, как ощущается работа аналитика, тестировщика или фронтендера. Роадмапы говорят, что учить, но не дают попробовать.

Сервис проводит человека от «не понимаю, что там делают» до **первой решённой рабочей задачи**: он попадает в рабочую среду, ИИ-тимлид выдаёт задачу, по смыслу такую же, как на реальной работе, но с поддержкой, соответствующей уровню человека. После задачи — фидбек, рефлексия и персональный роадмап на основе того, что человек реально сделал.

**Принцип:** LLM — интерфейс и наставник, а не источник истины. Результат задания проверяется **кодом** (детерминированно), а не мнением модели.

## 2. Пользовательский флоу

1. **Лендинг** — суть в одной фразе, кнопка «Попробовать».
2. **Выбор профессии** — 3 карточки (Аналитик данных, Тестировщик, Фронтенд-разработчик) + вариант «Не знаю, что выбрать» → 4 вопроса об интересах → рекомендация 1–2 профессий.
3. **Определение базы** — 4–5 вопросов с вариантами ответа (писал ли код, работал ли с Excel/таблицами, знает ли, что такое БД / HTML / CSS). Результат: уровень `novice` или `basic` (считается **кодом** по баллам, без LLM).
4. **Рабочая среда** — слева: описание задачи и интерактивная среда профессии; справа: чат с ИИ-тимлидом. Кнопки «Подсказка» и «Сдать задачу».
5. **Результат** — что получилось / что нет (по проверкам), сколько подсказок использовано, время, фидбек тимлида.
6. **Рефлексия** — 3 вопроса про конкретные моменты задачи (см. п. 6).
7. **Роадмап** — персональный план на 4 недели + «почему именно так» (ссылки на действия в задании) + кнопка «Попробовать другую профессию».

## 3. Стек

- **Vite + React + TypeScript + Tailwind CSS**. Роутинг: `react-router-dom`.
- **sql.js** — SQLite в браузере для задания аналитика.
- **CodeMirror** (`@uiw/react-codemirror`) — редакторы SQL и CSS.
- **LLM:** любой OpenAI-совместимый API (OpenRouter / Groq / Gemini OpenAI-compat). `BASE_URL`, `MODEL`, `API_KEY` — из переменных окружения.
- **Прокси для LLM:** одна serverless-функция (`/api/chat`, Vercel) или маленький Express-сервер, чтобы не светить ключ в браузере.
- **Деплой:** Vercel.
- Состояние сессии — в React-контексте + `localStorage` (обёрнуто в try/catch). Бэкенда/БД нет.

## 5. Контракты (types.ts)

```ts
export type Level = 'novice' | 'basic';
export type ProfessionId = 'analyst' | 'qa' | 'frontend';

export interface BaseQuestion {
  id: string;
  text: string;
  options: { label: string; score: number }[];
}

export interface CheckResult {
  passed: boolean;                 // задача решена
  items: { label: string; ok: boolean }[]; // что именно получилось/не получилось
  score: number;                   // 0..100
}

export interface EnvironmentProps {
  level: Level;
  onEvent: (e: SessionEvent) => void;          // логируем действия для фидбека и роадмапа
  onSubmit: (result: CheckResult, answer: unknown) => void;
}

export interface Profession {
  id: ProfessionId;
  title: string;
  shortDescription: string;
  baseQuestions: BaseQuestion[];
  levelThreshold: number;          // сумма баллов >= порога → 'basic'
  task: {
    title: string;
    briefing: string;              // первое сообщение тимлида: контекст и задача
    goal: string;                  // что считается успехом (для промпта тимлида)
    glossary: { term: string; explanation: string }[]; // термины, которые тимлид объясняет по ходу
    hints: Record<Level, string[]>; // подсказки по порядку, от общей к конкретной
    solutionForTeamlead: string;   // правильный ответ — только для промпта, НЕ показывать пользователю
  };
  reflectionQuestions: { id: string; text: string; options: string[] }[];
  Environment: React.FC<EnvironmentProps>;
}

export type SessionEvent =
  | { type: 'query_run' | 'css_changed' | 'bug_marked' | 'hint_used' | 'chat_message' | 'error'; at: number; payload?: unknown };

export interface Session {
  professionId?: ProfessionId;
  level?: Level;
  baseAnswers: Record<string, number>;
  startedAt?: number;
  finishedAt?: number;
  events: SessionEvent[];
  hintsUsed: number;
  chat: { role: 'user' | 'teamlead'; text: string }[];
  result?: CheckResult;
  reflection?: Record<string, string>;
  roadmap?: Roadmap;
}

export interface Roadmap {
  summary: string;                 // 2–3 предложения: как прошло, к чему склонность
  strengths: string[];
  gaps: string[];
  weeks: { week: number; focus: string; tasks: string[]; resources: string[] }[]; // 4 недели
  nextProfessionToTry?: ProfessionId;
}
```

## 6. Задания (главный контент)

Каждое задание по смыслу — настоящая задача джуна. Уровень меняет **инструмент и количество поддержки**, а не суть.

### 6.1. Аналитик данных — «Почему упали продажи?»
- **Легенда:** интернет-магазин, с 15 октября выручка упала на ~30%. Тимлид просит найти причину.
- **Данные (SQLite, ~500 строк):** `orders(id, created_at, amount, status, payment_method, region, platform)`.
  Причина заложена: с 15.10 резко выросла доля `status='failed'` у `payment_method='sbp'`. Остальные срезы (регион, платформа) — без аномалий, чтобы было что исключать.
- **novice:** конструктор запроса — выпадающие списки «Показать: число заказов / выручку», «Сгруппировать по: дате / способу оплаты / региону / платформе / статусу», «Фильтр». Под капотом собирается SQL и **показывается** пользователю (учит, как выглядит запрос). Результат — таблица + простой столбчатый график.
- **basic:** пустой SQL-редактор + схема таблицы + кнопка «Запустить».
- **Сдача:** пользователь выбирает причину из 5 вариантов и пишет одно предложение-вывод для тимлида.
- **checker:** верный вариант причины (детерминированно); бонус-пункт — был хотя бы один запрос с группировкой по `payment_method` (по логу событий).

### 6.2. Тестировщик — «Проверь страницу перед релизом»
- **Легенда:** завтра релиз страницы оформления заказа, нужно найти баги.
- **Среда:** React-компонент `BuggyShop` — мини-страница корзины с **5 заложенными багами**, например:
  1. сумма корзины не пересчитывается при изменении количества;
  2. можно ввести отрицательное количество;
  3. кнопка «Оформить» активна при пустом поле email;
  4. промокод применяется дважды;
  5. опечатка в цене доставки (показано 0 ₽, а в итог прибавляется 300 ₽).
  Элементы с багами помечены `data-bug-id`. Режим «Отметить баг»: клик по элементу → поле «Что не так?» → баг попадает в отчёт.
- **novice:** чек-лист «что обычно проверяют» (граничные значения, пустые поля, пересчёт сумм) + после 3 минут тимлид предлагает подсказку.
- **basic:** без чек-листа.
- **Сдача:** отчёт о багах.
- **checker:** засчитан баг, если отмечен элемент с нужным `data-bug-id` (описание — по желанию оценивает LLM в фидбеке, но не в зачёте). Успех — найдено ≥ 3 из 5.

### 6.3. Фронтенд-разработчик — «Поправь карточку товара по макету»
- **Легенда:** дизайнер прислал макет, а вёрстка карточки разъехалась.
- **Среда:** слева — эталонная картинка/рендер карточки, справа — живое превью карточки в iframe с CSS пользователя.
  Заложено 4 расхождения: кнопка не того цвета, картинка вылезает за границы, цена не жирная, нет отступов внутри карточки.
- **novice:** панель свойств (цвет кнопки — палитра, `object-fit` — выпадающий список, жирность — переключатель, отступ — слайдер); рядом показывается получившийся CSS-код.
- **basic:** CSS-редактор (CodeMirror) с исходными стилями.
- **checker:** `getComputedStyle` элементов в iframe сравнивается с эталонными значениями (цвет кнопки, `object-fit`/`overflow`, `font-weight >= 600`, `padding >= 12px`). Успех — исправлено ≥ 3 из 4.

### 6.4. Рефлексия (у каждой профессии свои варианты, связаны с типами работы)
- «Что было интереснее всего?» (искать причину в данных / писать запрос или код / находить ошибки / делать красиво по макету / объяснять результат тимлиду)
- «Где было сложнее всего?»
- «Хотел бы делать такое каждый день?» (да / скорее да / скорее нет / нет)

## 7. ИИ-модули

Все вызовы — через `ai/client.ts` → `/api/chat`. **У каждого вызова есть фолбэк** (`ai/fallbacks.ts`): если API упал или ответ не распарсился, показываем заготовленный текст. Демо не должно ломаться никогда.

| Модуль | Вход | Выход | Требования |
|---|---|---|---|
| `teamlead.ts` | профессия, уровень, история чата, последние события, `solutionForTeamlead`, glossary | реплика тимлида (до 3–4 предложений) | Русский, дружелюбно, как настоящий тимлид. **Никогда не выдаёт ответ целиком.** Объясняет термины, когда они впервые встречаются. На «дай подсказку» — следующая подсказка из `hints[level]` своими словами. Если пользователь молчит 2+ минуты после ошибки — сам предлагает помощь. |
| `recommend.ts` | ответы на вопросы об интересах | 1–2 `ProfessionId` + по фразе «почему» | JSON. Фолбэк — простое правило по баллам. |
| `feedback.ts` | `CheckResult`, события, подсказки, время, вывод пользователя | фидбек тимлида: 1 похвала по делу, 1–2 точки роста | Опирается на **конкретные действия** из лога («ты сразу сгруппировал по способу оплаты — так и делают аналитики»). |
| `roadmap.ts` | вся сессия + рефлексия | `Roadmap` (JSON по схеме) | Каждый пункт роадмапа привязан к тому, что было в задании. Реальные бесплатные ресурсы общего вида (документация, известные бесплатные курсы). Если рефлексия негативная — честно предложить попробовать другую профессию. |

Ответы, где нужен JSON, парсить с валидацией; при ошибке — один повтор, затем фолбэк.

## 8. Нефункциональные требования

- Работает на ноутбуке и на телефоне (жюри может открыть по QR) — адаптивная вёрстка, на мобильном чат тимлида выезжает снизу.
- Без регистрации.
- Весь интерфейс на русском.
- Аккуратный, современный дизайн: одна акцентная палитра, крупная типографика, ощущение «рабочего пространства» (чат в стиле мессенджера).
- Ключ API — только в переменных окружения сервера.
- В шапке — прогресс-бар по шагам флоу.

## 9. Приоритеты (что делать, если не успеваем)

1. **MUST:** флоу целиком для **одной** профессии (аналитик) на уровне `novice`, тимлид, проверка, фидбек, роадмап.
2. **SHOULD:** вторая профессия (тестировщик), уровень `basic`, рефлексия.
3. **COULD:** третья профессия (фронтенд), «не знаю, что выбрать», кнопка «попробовать другую».
4. **WON'T (говорим на защите как «дальше»):** больше профессий, сбор анонимной статистики «где застревают новички», привязка к учебным планам вузов, аккаунты.

## 10. Распределение работы (4 человека)

### Участник 1 — Каркас и интерфейс
- Первые 20 минут: репозиторий, Vite + React + Tailwind, **`types.ts`** и `SessionContext` — пушит сразу, остальные стартуют от этого.
- Все экраны из п. 2, роутинг, прогресс-бар, чат тимлида (UI), адаптивность.
- Деплой на Vercel, итоговая сборка всех частей.

### Участник 2 — Задания и проверки
- `professions/`: конфиги, среды и checker'ы. Порядок: аналитик → тестировщик → фронтенд.
- Генерация тестовых данных для аналитика (скрипт → `data.sql`), `BuggyShop`, превью для фронтенда.
- Каждая среда сначала тестируется отдельно на заглушке страницы.

### Участник 3 — ИИ-логика
- `api/chat.ts` (прокси), `ai/` целиком: промпты, тимлид, фидбек, роадмап, рекомендация, фолбэки.
- Ключи у **двух** провайдеров, переключение через env.
- Тексты подсказок и glossary — вместе с участником 2.

### Участник 4 — Продукт, тесты и защита
- Сценарий демо (кто что нажимает, какие ответы вводит), прогон всего флоу каждый час после 15:00, список багов команде.
- Презентация: проблема → решение → живое демо → «почему не ChatGPT» → как использовали ИИ в разработке (критерий 10%) → что дальше.
- Ведёт лог ИИ-пайплайна команды (какие инструменты, какие промпты, как делили работу) — для слайда.
- Записывает **резервное видео демо** к 17:00 на случай проблем с сетью.
- Готовит ответы на вопросы жюри (в первую очередь: «чем вы отличаетесь от roadmap.sh и от вопроса в ChatGPT?»).
